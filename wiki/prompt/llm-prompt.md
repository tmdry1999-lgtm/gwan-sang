# Ollama 프롬프트 틀 (A안)

## 역할 나누기

- **판정은 코드가 한다.** 오행형, 별점, 사주 오행, 괘는 브라우저 코드가 계산해 JSON으로 넘긴다.
- **LLM은 문장만 쓴다.** 넘겨받은 판정과 근거 문구를 말투 가이드에 맞춰 자연스러운 한국어로 엮는다.
- 이유: 작은 로컬 모델은 계산·판정을 틀리기 쉽다. 근거가 바뀌지 않게 하려면 판정을 코드에 둔다.

## 모델

- 이미지는 보내지 않으므로 텍스트 모델을 쓴다. 부스 노트북이 내장 GPU라고 가정하고 작은 모델부터: `gemma3:4b`, `qwen2.5:3b` → 느리면 `gemma3:1b`.
- 작은 모델은 느리므로 **종합 → 카테고리 순으로 나눠 요청**하고, 도착한 것부터 화면에 채운다. 기다리는 동안 다음 카테고리 자리에는 "읽는 중" 연출을 보여 준다.
- 한국어 품질은 부스 전에 직접 비교한다(설계서의 테스트 항목).
- Ollama `format` 옵션에 아래 출력 JSON 스키마를 넣어 형식을 강제한다.

## 시스템 프롬프트

```text
너는 전통 관상서(마의상법, 유장상법)를 바탕으로 체험용 관상 풀이를 쓰는 작가다.
독자는 학생과 학부모다.

규칙:
1. 입력 JSON의 판정과 근거만 쓴다. 새 판정이나 근거를 지어내지 않는다.
2. 각 카테고리는 "무엇을 봤나 → 관상서 근거 → 그래서" 순서로 2–3문장.
3. 해요체. 좋은 점을 먼저, 길게 쓴다.
4. caution 필드가 있을 때만 "~하면 더 좋아요" 형태로 조언 1문장을 쓴다.
5. 수명, 질병, 사고, 외모 평가, 성별 고정관념, 미래 단정 표현은 쓰지 않는다.
6. 한자어는 처음 나올 때 괄호로 쉬운 말을 붙인다.
7. 출력은 지정된 JSON 형식만.
```

## 입력 JSON (코드 → LLM)

```json
{
  "face": {
    "ohaengType": { "main": "토", "sub": "금" },
    "features": [
      { "id": "m14", "part": "콧방울", "level": "뚜렷이 좋음",
        "basis": "재백궁: 코끝과 콧방울이 도톰하면 재물을 담는 힘이 있다 (마의상법)" }
    ]
  },
  "saju": { "pillars": 3, "dominant": "토", "missing": ["수"] },
  "gwae": { "upper": "곤", "lower": "건", "name": "지천태", "meaning": "하늘과 땅이 통해 일이 풀린다", "timeSource": "체험 시각" },
  "categories": [
    { "key": "wealth", "label": "재물운", "stars": 4.5,
      "featureIds": ["m14"], "link": "사주 대표 기운 토 = 얼굴 토형",
      "caution": null }
  ]
}
```

## 출력 JSON (LLM → 화면)

```json
{
  "headline": "당신은 듬직한 토형(土形)이에요.",
  "summary": "2–3문장",
  "categories": [
    { "key": "wealth", "text": "2–3문장", "tip": "조언 1문장 또는 null" }
  ],
  "qrSummary": "QR 결과 페이지용 요약, 300자 이내"
}
```

## 실패 처리

- 15초 안에 응답이 없거나 JSON이 깨지면 → `app/data/fallback-texts.json`의 미리 쓴 문장 조각을 코드로 조립해 보여 준다. 부스에서 화면이 멈추면 안 된다.
